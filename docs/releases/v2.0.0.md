# SonarQube Offline Report Plugin v2.0.0

Status: unpublished tagged candidate, superseded by v2.0.1. No GitHub release
or assets were published for v2.0.0: the clean-tag workflow stopped before
publication when SBOM-specific attestation required a CycloneDX serial number.
The tag is retained and currently unmoved as an audit record, but repository
tag protection remains an open administrator control. Do not install this version.

Version 2.0.0 was an enterprise-candidate reporting and runtime-hardening tag for controlled pilot evaluation. The model-equivalent dirty v2.0.0 Linux lab candidate passed upgrade and rollback rehearsal; the clean tagged artifact was never published or deployed.

The candidate targets SonarQube Community Build `26.6.0.123539` and Plugin API `13.7.0.4381`. Other server/API versions are unsupported until they appear in the qualified compatibility matrix.

The major version is intentional: generated JSON advances from Report Model v2 to Model v3, portfolio artifacts add a new machine-readable contract, and CSV becomes a manifest envelope. Automated consumers must validate and migrate to the new schemas. Saved report templates remain backward compatible with template schemas 1 and 2.

## Highlights

- Adds Report Model v3 portfolio reporting for up to 50 visible projects, with bounded concurrency and independent project outcomes.
- Reuses one frozen collection snapshot and report ID across HTML, XLSX, DOCX, print, CSV and JSON exports.
- Separates `collectedAt`/`collectionCompletedAt` from artifact `exportedAt`, format and completeness metadata.
- Uses credentialed same-origin Fetch with real abort propagation and retains a compatibility request fallback.
- Adds explicit portfolio preflight limits: 25,000 requested issues and 50,000 components in total; DOCX registers are limited to 2,000 selected issues.
- Adds test-execution, coverage-denominator and per-file measure evidence without collecting source code.
- Was configured to publish CycloneDX SBOMs, SHA-256 checksums and GitHub build-provenance attestations; publication did not occur for this tag.

## Integrity and provenance

The release workflow serialized the tag, verified its commit was reachable from the default branch and agreed with Maven/npm declarations, removed checkout credentials before running build code, rebuilt and tested the browser bundles, ran Maven verification, reran the real-browser persona suite and bounded maximum export benchmark, and revalidated the remote tag before attestation. Repository-wide `refs/tags/v*` update/deletion protection remains an administrator-owned promotion control. The following intended assets were built but not published:

- `sonar-offline-report-plugin-2.0.0.jar`
- `sonar-offline-report-plugin-2.0.0.jar.sha256`
- `sonar-offline-report-plugin-2.0.0.cdx.json`
- `sonar-offline-report-plugin-2.0.0.cdx.json.sha256`
- `sonar-offline-report-plugin-2.0.0.provenance.json`
- `sonar-offline-report-plugin-2.0.0.provenance.json.sha256`
- `sonar-offline-report-plugin-2.0.0.validation.tar.gz`
- `sonar-offline-report-plugin-2.0.0.validation.tar.gz.sha256`

`collectedAt` and `collectionCompletedAt` identify the frozen collection snapshot. Each exported artifact has its own `exportedAt`; `generatedAt` remains only a backward-compatible alias for collection completion on an unexported snapshot and for `exportedAt` on an artifact clone. Report ID and collection timestamps do not change when another format is created from prepared data.

The failed run created general artifact attestations for its candidate subjects, but no release files were published and the separate SBOM-to-JAR attestation did not complete. v2.0.1 adds the required deterministic CycloneDX serial and repeats the complete build/validation/attestation sequence before publishing any asset.

Custom reproducible builds can supply `OFFLINE_REPORT_SOURCE_REVISION=<hex>` and `OFFLINE_REPORT_SOURCE_DIGEST=sha256:<hex>` when generating browser bundles. These values are validation inputs, not unchecked overrides: the revision must match Git when Git is available, and the digest must match the bytes computed from the declared `plugin-build-inputs-v1` scope. They identify source/build inputs; they are not a digest of the later browser download.
